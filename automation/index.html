CLAUDE CODE · MULTI-REPO WORKSPACE

Developer tooling · workflow automation

Giving a multi-repo AI workspace a nervous system.

A five-repository codebase where AI coding sessions run daily needs guardrails nobody can be relied on to remember. The answer is a lifecycle-hook automation layer: small, portable scripts that fire at fixed moments in every session to enforce safety, quality, and workflow — backed by a command layer for the work you drive by hand, a skill layer of packaged procedures, a scheduled layer for the checks that only fail slowly, and a review layer of specialist agents that audit what the scripts structurally cannot see.

Most of the automatic layer only advises. A minority can stop a command outright, and they split by posture: a small set of gates fail closed — they block what they cannot prove is safe — while the rest deny on a positive match and stay open when their own toolchain is degraded. Which posture a gate gets is the only interesting decision on this page, and it is made per gate, from what it costs to be wrong in each direction.

No counts on this page. The scripts, commands, and agents are added and retired continuously, and a permanent page quoting a moving number is a stale claim with a countdown on it. The shapes below are stable; the totals are not, so they aren't here.

Platform vs. build. Claude Code supplies the runtime — the lifecycle events themselves, the slash-command and skill mechanisms, and the hook-wiring format. What's documented here is the layer built on top of it: the specific scripts, commands, and skills, the choice of which event each hangs off, and the engineering decisions that make them safe to run unattended on every machine, every session.

01

Design principles

The hooks follow a few rules that keep them safe to run on anyone's machine, every session, without becoming noise or a liability.

posture

Fail open is not fail silent

A degraded toolchain makes a hook a no-op, never a hang or a false block — with deliberate exceptions for the gates whose false pass is unrecoverable (the secret scanner, the repo-identity guard, the publish gate), which fail closed.

That was the whole principle until it wasn't. Exiting zero is fail-open; discarding the error is a second, separate choice, made by habit, and it costs the entire diagnostic surface. Six defects in eight days were each hidden by the silence rather than the openness — including a gate whose “I could not evaluate this” branch was unreachable, so an unreadable input read as nothing-to-check and was allowed through. A hook can decline to block and still refuse to be quiet.

contract

Three outcomes, never two

Any check exits clean, violations found, or could not check — three states, not a boolean. The third is the one that matters: a detector reporting success when it never ran reproduces the exact bug it was built to catch. Four checks here had invented that distinction independently before it was made the project-wide convention; the other forty had none.

philosophy

Narrated → enforced

A convention written in a doc gets forgotten. Wherever a rule can be expressed as a check, it becomes one — so the guarantee holds even when no one remembers it, and self-clears the moment the check goes green.

portability

One script, every machine

The same hooks run on Windows and macOS with no hardcoded drive letters, python3-first resolution, POSIX-only tools and LF endings enforced. They reach every machine through one synced config repo.

This is not a hypothetical. The layer runs across two Windows boxes and a Mac, on more than one person's hardware, and a second contributor works inside it. Portability stopped being a design goal the moment someone else's machine had a different drive letter.

integrity

Single source of truth

Volatile metrics are computed once into one file, then propagated into docs and dashboards mechanically. A broken environment degrades to “no change,” never to bad numbers overwriting good ones.

concurrency

Multi-writer safety

Several writers — human teammates or AI sessions — share one multi-repo workspace. Git worktrees, a branch-per-task convention, and a live-session registry keep two of them from editing the same sub-repo and committing onto each other's branches — a real failure this layer was built to prevent. The coordination rides on shared git conventions, so it holds for teammates who have never touched an AI tool.

Where the repo-identity guard came from. A repository had been transferred between owners, which leaves a redirect behind. An archive command typed against the old name silently followed that redirect and archived the canonical repository instead — the one being kept. The check that catches it is a single API call asking whether the name you typed still equals its own canonical name; if it doesn't resolve, or resolves to something else, the destructive verb is denied. Nearly every gate on this page exists because something like that happened once.
Why the newest gates all guard something that isn't a file. The original guards protect a working tree: is it dirty, is another session in it. Then several sessions started running at once, and the collisions moved to resources a working-tree guard structurally cannot see — a remote branch being merged with no checkout, a shared project board with no repository at all, a work item two threads both decided to pick up. Each was quiet under every existing guard, and each cost real duplicated work before it got one of its own. The unit of contention was never the file.

03

The command layer

Alongside the automatic hooks, a set of slash commands drives the work you do by hand. Command first, purpose first — /thing does X so that Y.

Start & steer your work
/session-start
opens a development session — loads current state, git status, and the issue board so you start with full context instead of cold.
/status
prints a project snapshot — where things stand across repos, at a glance.
/my-work
lists the issues assigned to you across repos, so “what am I meant to be doing” is one command.
/start <#>
picks up an issue — creates the branch, marks it In Progress, and posts a pickup comment so the board reflects reality without you touching it.
/close-out
wraps a session cleanly — captures loose ends into issues, reconciles what you touched against the board, and flags stale items so nothing gets lost. (/session-end is a kept alias.)
Machine & environment
/doctor
checks a machine is ready — verifies the toolchain the hooks and commands depend on, and prints a one-line fix for each gap.
/whereami
confirms which machine you're on — reports host, hardware, and a task-fit verdict so heavy work doesn't run on the wrong box.
Domain commands
The project adds several more commands of its own for running and checking the simulation — launch a run, audit module wiring, grade calibration against reference data, stress-test scale, rebuild the dashboards, and report automation health. Specifics are omitted from this public write-up.
04

The skill layer

Skills package multi-step procedures the agent invokes on demand — each one a repeatable workflow with its own instructions and helper scripts, so a complex task runs the same way every time.

publish-safety scrubber

Scans an outward-facing file for confidential terms against a maintained registry and rewrites them before it can leave a private repo.

citation verifier

Validates a reference against a public index at the moment it's written, so a wrong attribution never lands in the source.

automation-placement advisor

Decides whether a new automation belongs in CI, a local lifecycle hook, or a scheduled job — and whether it's safe to run.

document generator

Builds branded documents from a single canonical content source, so figures and numbers never drift between formats.

Two further skills cover session self-review and an archival export routine.

05

The scheduled layer

Everything above fires on an event: you typed something, or the session started. That covers every failure with a moment attached to it — and none of the ones that accumulate. So a small set of sweeps runs on a calendar instead.

weekly automation audit

Dispatches the hook-health reviewer on a fixed day and files each genuinely new finding as an issue, de-duplicated against the open ones so an unfixed problem isn't re-reported every week.

weekly board integrity sweep

Reconciles the tracker against itself — closed work still showing as in-progress, rows that drifted out of sync — and regenerates the outward change record from source.

Why a cadence, and not just better hooks. The hooks here are fail-open, which means a hook that has stopped working is indistinguishable from one that found nothing. One month produced four such silent no-ops: a path filter written in the singular against a plural directory, a registry alias nobody scanned, a whole publish surface never registered, and a fallback that had never once fired. Not one of them surfaced on its own — every one was found by accident, while someone was looking at something else nearby. A recurring sweep is the only thing that finds a failure with no event to hang off.
Findings go to the tracker, never to notes. An earlier scheduled job wrote its results to the agent's memory, and a live grant deadline sat unread there for sixteen days. Memory isn't reachable mid-task; the issue tracker is the one surface that is already in the path of the work. Where a finding lands decides whether it is ever seen.
06

The review layer

The last layer exists because of something the others can't fix. A script only looks for what it was told to look for, where it was told to look. Three specialist review agents read for the things a pattern can't express — and each one is scoped to a blind spot I could name.

pre-publish IP reviewer

Reads a finished outward-facing artifact the way a hostile reader would, and returns a verdict — block, revise, or clear. It exists because the write-time scanner is a path filter, and a path filter can only protect the directories it was told about.

hook-health auditor

Audits the automation layer for silent failure: filters that match nothing, swallowed errors, dead references, drift between the config and what's on disk. Fail-open has a cost: a broken hook and a clean run look identical.

backlog triager

Reconciles the issue board, syncing the mechanical facts on its own and escalating only the judgment calls — priority, and what to cut. Facts are the agent's, values are the founder's.

The pattern across all three is the same, and it's why this layer is separate rather than more hooks: a check that fails open is indistinguishable from a check that found nothing. Every automated gate here is quiet when it passes, so each one is paired with a reader whose entire job is to assume the gate didn't run. Together, the five layers share one design goal: make the right thing automatic, and the wrong thing hard.

These now fire without being asked, and that was the fix. For its first weeks the review layer had to be invoked deliberately — which meant the pre-publish reviewer, whose entire job is catching what the write-time scanner misses, was slower than skipping it. That is backwards for a control, and the layer went almost unused: built, wired, and idle. Each agent now has a documented trigger it fires on by itself. A safeguard that competes with the deadline loses to the deadline.

Why it's built this way

An AI coding agent is fast and tireless, but it forgets between sessions and it runs on whatever machine happens to be in front of it. The value of this layer isn't any single script — it's that the guarantees survive the forgetting: a secret can't be committed, a metric can't drift, two sessions can't silently clobber each other, and a convention no one remembers is still enforced because it was turned into a check.

Every design choice trades toward safety-under-degradation: fail open so a broken toolchain never blocks real work, fail closed on the handful of gates where a false pass is unrecoverable, keep the errors even where the block is waived, and make every script portable enough to run identically across every machine in the group from one synced config repo.
