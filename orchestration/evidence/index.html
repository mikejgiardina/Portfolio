ENGINEERING CASE STUDY
PROCESS · MULTI-SESSION ORCHESTRATION

Evidence appendix · the case study is here

The full record, round by round.

This page is the appendix to a case study about running several AI coding sessions at once. That page makes the argument in about twenty minutes. This one carries the evidence it rests on — every table, every round, every instance, and every note about which figures are not comparable to which.

It is long on purpose, and it is meant to be checked rather than read through. If you arrived here from a specific claim, the section numbers match the ones cited there.

Twenty-eight rounds of that, against a multi-repository workspace. This page is organised around the four things that survived: the mechanism (leases plus a single writer for everything serial), the defect class that showed up in every round — a check narrower than the claim it supports, which fails by passing — what the coordination actually costs, measured on two instruments that do not convert into one another, and the rubric eventually written to count the defects, which changed the measured rate by a factor of ten without the work changing. Round numbers appear as evidence, not as chapters.

The load-bearing discipline is that from round 9 the prediction was written down before each round and scored afterward. Eight registered predictions have missed. Two of those misses were followed by the bar being moved onto the round that had just missed it — the thing this page says you must not do, done twice before the rule existed. One round could not be scored at all, and that turned out to be the more useful result: the same night's work returned 6.40 or 2.67 on one agreed denominator, depending only on how finely the instances were counted, and nothing in the series said which was right.

And at round 26 the practice was retired — not abandoned, retired, with the grounds written down. The band had been missed high and low on adjacent rounds; the intake rule underneath it had changed by a factor of ten; and a count of the manifests found the band recorded under eight different key spellings and read by nothing. A predicted range was doing no work that the rubric underneath it was not already doing better. What replaced it is the more interesting artifact, and it is what section 05 is about.

01

The mechanism: leases out, one writer back

The failure mode that motivates everything: two sessions given clearly unrelated jobs, both of which turn out to need the same file. Topic independence does not imply file independence, and you find out at merge time.

None of this is new. Locking schemes, CODEOWNERS, monorepo ownership boundaries and branch policies have partitioned work by file ownership for decades. What is specific to the AI-session case is that the workers can't negotiate. Two engineers who both need the same file talk to each other, usually before either has finished. Two sessions don't. They both write it, and the merge is the first anyone hears about it.

the unit

A lease is a repo plus globs

Not “you take auth, you take docs.” A lease is (repository, [path globs]) — a concrete, enumerable set of files a session is permitted to write. Everything outside it is read-only to that session.

the check

Disjointness is verified, not assumed

Before any session is spawned, the glob sets are expanded and intersected. A non-empty intersection is a planning error, caught in a few seconds, rather than a merge conflict discovered after both sessions have finished.

the isolation

One worktree per lease

Each session gets its own git worktree and its own branch. The lease says what a session is allowed to write; the worktree makes it physically impossible for two of them to be editing the same working copy at once.

the consequence

Topics can overlap freely

Once the partition is by file, two sessions are allowed to be thinking about the same subject, which happens more than you would expect, and is fine. What they may not do is write the same line.

Where this leaks, and the leak has a measured instance. A lease constrains writes. It does nothing about a session reading a file another session is halfway through rewriting, so a worker can build correct work on a premise that's being invalidated underneath it. Nothing automated catches that. What catches it is the coordinator reading the diffs as they come back, and scheduling — two leases known to sit on either side of a shared assumption go in different rounds. Both are conventions rather than checks, and the sibling write-up on enforcement is blunt about what a convention is worth.

Round 20 is the round where that got measured rather than argued. A planned third lease was cut before spawn: its path globs were disjoint from another lease's — the check passed — but the two would have contended over the content of shared baseline files, because one of them was rescaling a value the other's fixtures encoded. The previous round had made exactly this mistake in reverse: it verified parallel safety on paths, found zero overlap, and that was true while the claim that mattered was about content. Path disjointness is a necessary check that has been mistaken for a sufficient one.

rounds 28 and 29 · the gap written up with its own missing evidence

The caveat is what made the instance findable

At round 28's close the closing session wrote that gap up as a tracked item rather than a remark. The lease model gates on paths, and the hazard is content. Two workers can hold perfectly disjoint write globs and still break each other, because one of them changes a constant, a contract or a threshold inside a file only it holds, and the other's files read or assert against that value. Both merge clean. No lease is violated. Nothing fires. The check answers “did two sessions write the same bytes”; nobody is asking “did one session invalidate a baseline another is reading.”

It was filed with the hole in its own evidence stated in the issue body. The one measured instance available involved a shared file — a single line every worker had to edit — which is the coupled-content hazard in its easy form, the one a path check could in principle see. So the filing said, in as many words, that there was no measured instance of the pure form, that it asserted a structural gap rather than an observed failure, and that it should not be quoted as the latter.

That caveat is the reason an instance exists. The next round's coordinator went looking for the pure form in its own governing document, and found one there — in the manifest's own justification for running three concurrent lanes, which argued entirely from disjoint write surfaces and asserted that the single seam anyone had identified was removed. Removing that item removed the file overlap. It left the semantic dependency standing.

The shape, which is all that transfers. One feature's only call site pulls an event predicate and a text-shaping helper from the first lane's surface, hands the result to a downstream function owned by the second, from a component owned by the third. The contract between them is a shared formatting convention, written as two separate expressions in two files belonging to two different lanes. No two lanes share a path. All three branches would merge clean, the disjointness check would confirm it, and nothing would fire.

Cite it with its qualification, because the qualification is the point. This is a predicted break and not an observed one — no lease had started, and that was verified rather than assumed. It is a measured contract across measured-disjoint surfaces, with the failure modes traced to source. It is not a defect that landed and must not be read as one. That round — round 29 — was still running when this page was published, and nothing here is a report of its outcome. What it does establish is that the pure form is neither hypothetical nor rare: it turned up in the first round anyone looked, in the document asserting the isolation.

Ownership is recorded as shared, and the split is the part worth reading. The sentence was authored at prep by the same seat that had filed the issue one turn earlier. The coordinator then read it, relied on it to spawn three lanes, and restated the disjointness argument in a brief of its own without checking it. The author offered to take the whole thing; the coordinator declined the whole of that, on the ground that inheriting a claim and repeating it in a document of your own is not the same as not having made it. Neither party classified it. It routes to the one reader who owns neither.

A control whose subject is cheap to check rather than the one that matters. Paths are easy and semantics are hard; names are easy and shape is hard. Both report clean, and in both cases silence and a pass are the same bytes. the sentence that covers this and the merge that closed nothing equally
the case where the primitive didn't fit · run anyway

Two sessions, one file, partitioned by intent

This page was the test. Two sessions worked on the same file at the same time — one owning the prose, one owning the visual system — because the boundary was what kind of change, which is not expressible as a path glob. A lease could not describe it.

It merged with zero conflicts. That is not the finding. The partition held because one session sent the other the exact strings to grep for after rebasing, and why each one mattered. Without those two messages, a routine “keep mine” resolution restores a claim that had been removed from a live public page for cause.

It would have failed. It was rescued by out-of-band coordination that the model does not require and cannot enforce. The clean merge is evidence that two careful participants can compensate for a primitive that doesn't apply. It is not evidence the primitive works.

The round's actual collision was not the contested file. It was a squash race on a branch nobody was contending: commits pushed after a squash-merge landed on a closed PR and were silently never published. Path leasing does not address that and would not have caught it.

A lease carries more than paths

The globs prevent collisions. Two other things get assigned at the same time, and a third is meant to be and turns out not to be — which is the one people are most surprised by.

meant to be, but is not

A model, per lease

The intent is that the planning layer sizes each lease to a model: mechanical work does not need the expensive one, and the lease that has to read a bad premise and argue back does.

Round 6 measured it and it is not what happens. Every thread ran on the top tier, because the spawn call has no model parameter at all — a coordinator structurally cannot set a lease's model when it creates it.

assigned at spawn

Permission to fan out

A lease can be granted the right to spawn its own subagents, and it decides — it is closer to the work than the coordinator is.

The lease still owns the result. Whatever its subagents produce arrives as that lease's output, under that lease's globs, which keeps the collision guarantee intact no matter how wide it went underneath.

assigned at spawn

A scoped pre-authorization

Dated, revocable, and naming exactly which otherwise-gated files this lease may touch — plus a park and report list for things it may not, and a hard-decline list. A worker that has to stop and ask about every gated file is not running in parallel with anything.

The model-tier gap is half reachable and nobody reached for it. What a lease can select is the model for the subagents it spawns itself, and round 3 measured those sidechains at 28% of worker output, ranging 0–50% by lease. That half was available the whole time, because the brief said “spawn subagents freely” and never said “tier them.” The general form: an unspecified subagent inherits the most expensive setting available. The failure is a silent inherited default, not a wrong decision.

Centralize the serial resources

Some resources cannot be written by two sessions at once without one of them losing. The rule is not “coordinate carefully” — it is route them through one writer and let everything else run free. Four qualify.

The tracking board

Two sessions updating the same board produce last-write-wins, silently. Workers report status to the coordinator; the coordinator writes the board. The cost is a round-trip; the benefit is that the board is never wrong.

Merges to the default branch

Serial for the ordinary reason — each merge changes what the next one is rebasing onto. Also serial for a second reason specific to this workspace: the default branch of one repository publishes on merge, so a merge there is an irreversible outward-facing act and gets a human in the loop.

Shared file sinks

The handful of files every worker legitimately wants to append to — a changelog, a metrics file, an index. These are precisely the files a topic-based partition collides on. Leasing them to nobody and having the coordinator write them is simpler than any locking scheme.

Work intake

Workers surface findings; they don't file them. Four sessions filing issues independently produces duplicates, inconsistent labels and no dedup. Findings come back as text and the coordinator decides what becomes an item — which is now a job with a tool behind it rather than a chore at the end of a round.

The test for whether something belongs on this list is not “is it shared” — almost everything is shared. It is: if two sessions did this simultaneously, would the loser know? A merge conflict is loud and therefore safe to leave distributed. A board overwrite is silent, so it gets centralized. That test is the same one that produces section 02.

holding the line

“Holding receipts is not the same as owning the sink”

One worker finished holding better information than the coordinator about a batch of pending merges — the ordering, the evidence, all of it — and was offered the merges. It declined, in those words.

It was right. The value of a single writer is that it is unconditional; an exception granted to whoever currently seems best-informed is not a rule, and the next round has no way to know the exception was ever made.

and again, from the other side

A lease refusing its coordinator's own exemption

Round 20: the coordinator offered a lease permission to delete a stale file just outside that lease's globs. The lease declined and chose the route that reached the same end state without a write — “a hub's offer is not a grant; the brief is the grant, and the two are not the same document.”

Then it supplied what the coordinator actually wanted instead: a fingerprint identifying which file was the stale one. The mitigation without the exemption.

the coordinator's own failure

Touching a lease's tree mid-run

The coordinator applied an update to a shared file while a worker's test matrix was still running against it. Nothing errored. But there was no way to tell whether the run had read the file before or after the change, so the result was uninterpretable and had to be discarded.

The rule that came out of it is one line: if you must touch a lease's tree, tell it first. The single-writer discipline binds the coordinator too.

What centralizing the merges actually buys

The technical argument for one merger is rebase ordering. The argument that matters more in practice is about where the waiting happens.

Routing all of it through the coordinator turns that into one decision at the end. Click, click, click, click becomes click. That is the actual return on the pattern for a single operator, and it is much larger than the throughput gain — round 1 skipped it, gated every step on a human, and is the round with no usable timing numbers precisely because it was spent waiting.

The cost, stated plainly: the safe path is slower than the unsafe one, and it stays slower. Round 20's merge gate cost the round real time in two different arms — its evidence requirement produced a green tree with no legal path to land, because the evidence cannot be produced in a freshly created worktree and the model creates those by design; and its ownership arm refused a valid merge outright, over a name canonicalised one way on one side and another way on the other. Every step of both is individually correct. The round filed them and weakened nothing. Its own closing record was then the last artifact to land, hours behind the work it describes, because the reviewed route needs an approval the closing session cannot give itself — while everything else that round took a route that did not stop. Every incentive there points away from the reviewed route, and all the pattern does about it is make the wait visible. It did land, after this page had already said it had not.

The loop this closes

Intake, leases and merges aren't three policies. They're one cycle, and the board is both where it starts and where it ends.

1The coordinator reads the board and builds the teambounded by written rules

Open items are evaluated against the standing guardrails — process SOPs, decision records, persistent memory, repo configuration — then grouped by the write surface they need. Globs get intersected, and each lease is sized. Issues are assigned to whichever lease already owns their files, so one lease may carry several unrelated items.

2Each lease works in its own contextand evaluates on its own terms

A lease sees its own surface in far more depth than the coordinator can. It is expected to disagree with the item it was handed if the item is wrong, and it reports back rather than acting outside its globs.

3The coordinator reconciles what came backthe expensive step

This is the part that doesn't parallelize and the part that costs. Several leases report from several vantage points, and one reader has to hold all of it at once: which findings are the same finding, which contradict, which change what another lease was told, what merges and in what order.

4It writes the board, which is the input to the next rounddeduped, single voice

Findings become items here and only here, filed by the one participant that saw every lease's output. Either the same coordinator carries on, or a fresh one starts from the board it just wrote. Nothing has to survive in anyone's head between cycles, which is what makes it a loop instead of one very long session.

02

The check that is narrower than its claim

Across every round the same class kept turning up, in unrelated parts of the system, found by workers who were not looking for it: a failure whose symptom is a green result rather than an error. It is the most transferable thing on this page. As a rule: a check that cannot fail loudly will eventually pass quietly.

shape one · checked the wrong thing, reported pass

The gate that scanned a directory nothing was in

A gate ran its scan from a working directory that was not the one being changed. It found no problems there, because there was nothing there. It reported pass, correctly and uselessly, for every run.

Nothing about the output distinguished “scanned and clean” from “scanned an empty place.” Both are the same green. The general fix: make a check assert that it examined a non-zero amount of something, and fail if it did not.

shape two · passed because the input was empty

The test whose fixture never arrived

A test asserted that a bad input produces no output. It passed. It would also have passed if the tool under test had never run at all, and that is what was happening, because the fixture resolved to nothing.

An assertion of absence is satisfied perfectly by a test that never executed. The counter-measure is structural rather than clever: every “stays quiet” case is paired with a “makes noise” case over the same wiring. If the noisy twin is silent too, the harness is dead, and now you can tell.

shape three · read as done, did nothing

The merge that appeared to close three items and closed none

A pull request body listed the items it resolved using a shorthand that reads naturally to a person and matches nothing at all to the platform parsing it. The PR merged. The summary read as though three items had been closed. Three items stayed open, and nobody looked again, because the message said they were handled.

no component failed. The merge succeeded, the text was accurate English, and the outcome was silently nothing. It was caught by a sweep that reconciles merged pull requests against the items they claimed to close — which exists now precisely because reading the PR body was not enough.

round six · the same defect inside its own fix

An assertion that was its own witness

A test asserted that a protection existed by searching for a literal string — on a line that itself contained that string. Delete the protection entirely and the search still matches itself. What it was failing to guard was a live write to a shared project board.

Then the fix reproduced it. The worker built a detector for that whole class, and a control to prove the detector worked. The control carried its own copy of the pattern, so it verified that a detector like this can fire, not that this detector fires. Breaking the real detector left the control green. Found only because the worker mutation-tested a control that nothing required it to mutation-test.

And once more, at the tooling layer. After merging a PR out from under a still-working lease, the coordinator used a flag meaning “don't delete the branch” on the next merge and stated in writing that the branch was preserved. The lease checked. It was not. The flag parses correctly and the call is correct, but the repository is configured to delete branches on merge, so the platform removes it server-side and the flag exits zero having achieved nothing. It was one step from being written into the playbook as a safeguard.

round twenty · four instances, four different kinds of artifact

The same shape in a docstring, a stamp, a kill, and a page of documentation

A guard whose docstring promises what it structurally cannot deliver. A test's own docstring says it catches a stale data file. It compares membership counts, and the staleness it exists to catch moves a grade, not a membership. The one item that moved sat in the same partition on both sides, so the totals matched on the stale tree and the fresh one, and the test passed both times. The docstring does the damage, not the assertion — a reader greps “is staleness guarded?”, finds this test, reads the promise, and stops looking.

A provenance stamp that certifies numbers it never opens. A tool verifies that the working tree is clean and on the default branch, then stamps the metrics file it writes as coming from that verified state. Eight of that file's fields are read from an artifact in a different repository, of unknown age, outside the tree that was checked. The stamp reports full confidence about numbers it never read, and the artifact carries no commit, timestamp or digest, so its staleness is undetectable by construction. That instance was 29 days stale, and the discrepancy it produced had been blamed on line endings.

A liveness probe that answered about the wrong namespace. A worker wrote a guard to stop two of its own runs racing, checking whether the older process had exited. The probe was a POSIX-shell process check run against a native Windows process id — a different id namespace entirely. It returned “no such process” for a process that was very much alive, in zero seconds, and the second run launched into the first. It failed in the direction that looks like success.

And a page of documentation that is right about the mechanism and wrong about its scope. A configuration note describes a verification gate accurately, including the sentence that it cannot be fooled about coverage — then states the coverage as three legs where the gate requires four. A reader who trusts it runs all three legs, watches every one pass, and is refused, having followed the documentation exactly. The reassurance is what makes the reader stop checking. Same shape as the docstring, with a document as the subject.

rounds twenty-five and twenty-six · the same family, and what actually caught it

Eight instances, four parties, one rule all four had read

Round 25's strongest result is not any single instance. It is eight instances of one family — a check returning a confident number over the wrong subject — produced by four different parties, every one of whom had read the rule that names the family. Knowing the class is not a defence against it, and this is the round that put a number on how little it defends.

What caught them was never the knowledge. In all eight it was an assertion that made the failing case loud: a floor on how much subject the check had to have examined, a coverage check that ran in both directions, a grep for failure vocabulary rather than for success vocabulary, a row count that would not close. Never the rule. The transferable form is the one the round wrote down: when a check and its subject disagree, print the subject before believing the check.

Round 26 is the same shape with a sealed record as its subject. That round's headline, as first written, said the hazard it had hit was structural and that nothing could have caught it. Both clauses were false, and the second is the load-bearing one: the countermeasure had been sitting in the series' own protocol, in bold, addressed to exactly the party that needed it, for over a month. A round reading the original would have built a detector for a hazard already named. The correction was made additively — the original headline is still on the row, beside the amendment and the ruling that produced it, because the ledger records both readings and never converts silently.

The class gets harder to see, round on round. Round 12 found five capabilities that were built, correct, tested and unreachable — a restart that halted in a final state, a control wired to one console, menu items with no caller, a user mode whose setters never ran, a dashboard imported and never rendered. From outside, the features were “just kind of not there.” They were all there. Round 13 is the inverse and one degree worse: a correction declared in three documents and written in none. Round 16 sealed its cost as unmeasurable and blamed itself for never running the tool, which, run later, returned both workers unresolved anyway. The sealed explanation was true and was not the reason. Round 17 is the class one layer up: a repair to a matcher that had been silently passing everything merged, and was not in force, because the automation runs out of a checkout 43 commits behind. And round 18 refused its own good news — four of four workers resolved against one of six, and the round wrote down that pre-creating their directories was not why, because the previous round did that too and joined none.

Why an orchestration round is unusually good at finding these. A worker arrives with no memory of why anything was built and no stake in it being correct. It reads a check the way a stranger does, and a stranger is the only reader who notices that a pass proves nothing. The same blindness that makes a session useless for judgment calls is what makes it excellent at this specific job.

It also recurs one level up, in reasoning rather than in code. Round 20's coordinator made 14 recorded errors, and every scored one had the shape of the four above: a conclusion drawn from a command that did not range over the question. Two, both caught by the worker they were aimed at — a release command that named a resource by its qualified spelling while the thing being released was registered under its bare name, so it silently cleared nothing and a stale hold sat over a live lease's exact write surface all round; and a verdict that a run should be discarded as stale, delivered as fact, which the lease disproved by reading the run's actual output. It had passed, and had found two real defects.

Putting a number on it, and five rounds of the number missing

Through round 19 this class was a recurring observation. Round 20 registered it as a rate, with a band, written before the round existed, and it was registered before every round through 25. Five rounds were scored against it. It failed high twice, failed low once, and once could not be scored at all, and the one time it held is the least informative of the five. At round 26 the band was retired — that is section 04, and the rubric that outlived it is section 05.

The prediction is written by the previous round's coordinator and committed before any lease exists, so the coordinator that executes it starts cold and could not have shaped its own bar. A round that goes hunting for this class always finds some, so a dedicated sweep is a different instrument and inadmissible. In round 20 no sweep ran, and the one candidate whose own text asked for exactly that sweep was deferred, on the content collision from section 01, measured independently of the scoring so the deferral could not be a scoring convenience.

Round 20's audit ran in the direction that made the result worse, and so did round 21's. Round 20's coordinator excluded 8 of its 14 errors from the count, each with a written reason. A separate closing session, seated inside the round but not measured by it, walked all 14, upheld six exclusions and overturned two, on the ground that the stated reason for excluding them did not distinguish them from instances that had been scored. A third it judged genuinely ambiguous and declined to score, resolving the ambiguity against the number it was auditing. The rate went up. Round 21's audit moved 2.99 to 3.32 the same way. Two consecutive independent audits, both moving the published figure against the interest of the party that recorded it, and both published at the worse number.

And in round 20 the field that exists to make the exclusions auditable had itself gone stale. A summary block opened “five of seven are excluded…” and listed five. True when written. Three more were added later and never appended, so the summary disagreed with the map it summarised, and the wrong count propagated into the brief the closing session was handed. A stored summary that nothing recomputes, inside the one field whose entire purpose was exclusion integrity.

The one thing that stops a live count from being a story told afterward is recording the crossing before it happens. Round 20's coordinator did: at 12 instances, the band ceiling, with two leases unmerged and merges being where the round had been finding these most densely, it wrote into the manifest that the prediction was likely to fail high, that its behaviour would not change, and that none of the standing exclusions would be revisited to make room. At 13 it recorded the failure at the moment of crossing. The instance that crossed the band was a worker's self-reported defect rather than one of the coordinator's own, so the failure cannot be read as the coordinator padding its column.

round 22 · the result was that there was no result

Round 22 kept no running tally. Nothing was marked as counted while the round ran, so the numerator had to be reconstructed at close from five interim reports, and reconstruction is exactly where the choice of counting granularity lives. On the auditor's enumeration, 36 instances and a rate of 6.40. On the round's own naming, 15 and 2.67. Same night, same work, same denominator, re-derived by execution rather than quoted.

Nothing in the series constrained that choice, so the verdict spanned pass to fail on counting granularity alone. It was escalated rather than picked, and the round sealed unscoreable against its own primary prediction. The uncomfortable detail is that this was a known defect with a known fix: it had been filed as an issue against round 21, which had a tally script, and round 22 regressed past it. Round 21's verdict survived its entire audit range. Round 22's audit range contains the decision.

A remedy that has to be remembered is not a remedy, and round 23 is where that got tested. The counting rule was written into the plan before the round opened, in a form specific enough to apply rather than interpret: one instance is one check, in one artifact, whose stated claim is broader than what it ranges over. Not one finding, not one reader site, not one issue. A defect found at forty sites by a single check is one instance; two checks sharing a root cause are two. Each instance was then appended to the manifest at the moment it was scored, rather than assembled at the end.

That the tally really was append-only is the one claim here that was verified rather than asserted, and not by the party it constrains. The instrument was wrong twice, and the third time it was right

Every cost figure has a weakness no amount of care fixes: it was computed after the round, by someone who already had a belief about what it would say. Two separate defects were found in the tool that produces these numbers, and neither was found by looking for it. The third failure is the interesting one, because the tool was not the thing that was wrong.

First: the window selected sessions but never filtered messages inside them. Harmless for a lease, whose session begins when its chip does. Not for the coordinator, whose session predates the round and outlives it, so pre-flight and post-close work both counted as coordination. Corrected, round 6 falls from 25.9% to 20.9% and round 5 rises from 31.0% to 33.4%. The correction has no direction, and that is the point. A fix that only ever shrank the number would be a discount, and a discount that flatters whoever applies it is not a finding. What it buys is that the number stops depending on when you look: re-run on the same round 6 data an evening later, the uncorrected tool said 50.3% — 24.4 points of drift from elapsed time alone, on a figure nobody had touched. An independent session ran the re-measurement, because the correction moved a predecessor's number in its favour.

Second: the join excluded any session whose first message predated the window, instead of testing whether it had messages inside it. Workers boot, then the coordinator stamps the start time on the first acknowledgement, so they routinely lose by 30–40 seconds and resolve to nothing. Round 19 resolved 0 of 3 leases against its own manifest. The tool had a guard for the adjacent failure, but it only fires on sessions that matched, so one excluded before matching never reaches it. Guarded against being windowed to zero, unguarded against being excluded to zero — section 02's shape, inside the instrument that measures section 03.

Round 20 fixed it at open and verified the fix before trusting what it produced. The closing session ran the commit before and the commit after against the previous round's sealed manifest, unedited: leases resolved 0 of 3 → 3 of 3 while the coordinator's own figures stayed byte-identical — 184,554 output, 141 messages. The fix is two hunks, both inside the worker match; the coordinator match does no windowing at all, so it is untouched by construction rather than by assertion. Round 20 then resolved 4 of 4 seats first attempt, the first round in the series where that is true.

Then round 23 resolved zero of six, and the tool was not at fault. Its worker join keys on the session's working directory, and all six of that round's workers were started without one, so they rooted at the workspace top rather than inside a worktree — the exact case the join exists to ignore. Two controls run against the same code on the same day resolved 3 of 3 and 4 of 4. So the failure is in the round's spawn configuration, not in the measurement, and the distinction is only available because the controls were run before the conclusion was drawn.

What the two earlier corrections bought is visible here. Faced with a join it could not make, the tool exited non-zero, printed its unresolved rows, and refused to print the coordinator share at all, on the recorded ground that a share over half a denominator is arithmetically fine and substantively meaningless. An earlier version of the same tool would have printed a number. The measurable improvement across this series is not accuracy. It is the instrument's willingness to return nothing, which is the harder property and the one that makes the rest of the table worth reading.

The parallelism gain is real over the opening burst and does not survive the round. Round 3's four workers spawned within 5.5 seconds of each other and consumed roughly 291 minutes of working time in 152 of wall-clock — about 1.9×, and an upper bound, since only idle gaps long enough to detect were subtracted. Across the whole round it collapses to 1.1×, which is not a finding about parallelism but an artifact of one session left open overnight. Elapsed time is not working time, and nothing here distinguishes them — nor does anything distinguish “paused on a rate limit” from “thinking.”

One architectural claim has been measured, once. Across round 5, nine timestamped panel readings were tied to known points in the round. The coordinator's context grew from 151k to 380k tokens in 80 minutes, and the endpoints are consistent with no step at the moment the leases were spawned: two workers reporting through the coordinator cost it almost nothing in context. That is the central claim of the whole approach, measured this once — on four points, one round, two leases, with a 41-minute gap inside which a step would be invisible either way. What would break it is a round where context inflects at spawn, and none has been run to look for one.

Is there a standard for this?

No. Three established frameworks sit nearby and none measures what this page measures. DORA — deployment frequency, lead time, change failure rate, time to restore (Forsgren, Humble, Kim, Accelerate) — measures outcomes, not cost per unit of output. SPACE (Forsgren, Storey, Maddila, Zimmermann, Houck, Butler; ACM Queue 19(1), 2021) argues that productivity cannot be captured in a single metric and that activity counts mislead — the most citable thing in the area argues against the number people ask for, and that applies to every figure here. Agentic benchmarks report cost per resolved instance, the closest published analog to the per-PR figures above, but that is a reporting convention assuming a fixed task distribution, and production work is not that.

So the defensible sentence is the narrow one: these specific things were measured, those are the nearest frameworks, and I am not aware of a standard for what is actually being measured here. No conformance is claimed to any of the three.

the rule that made both decisions, stated once

Tighten on a mechanism, never on a spread.

It settled two arguments in opposite directions in the same week. Round 22 declined to narrow the class-rate band onto the span its three recorded points actually occupied, 2.99 to 3.10 against a band a hundred times wider, even though the tighter band would plainly have been the stronger test — because the only argument for tightening it was that the wide one kept passing. Both moves would have been improvements by the numbers and neither had a mechanism behind it, which is the same defect the whole page is about, arriving as a methodology decision instead of a failing check.

What holding a prediction across five rounds actually cost. One round sealed unable to score itself. One spent a closing session reconstructing a numerator that should have been written down as it went. Two consecutive audits moved the published figure in the direction that made it look worse, and both were published at the worse number. The class rate was registered in advance five times and landed in band once, and the case for the practice is not that the numbers came out well. It is that a figure nobody registered in advance cannot come out badly, which is why rounds 16, 18 and 19 have the most flattering readings in the series and none of them count for anything.

Retiring it, and measuring the thing before retiring it

Round 24 failed the band upward one round after round 23 failed it downward. A bar missed high and low on adjacent rounds is not a bar you are failing; it is an instrument you are not reading. What happened next is the part that distinguishes this from quietly dropping a metric.

The band was scored FAILED on an instrument change rather than on performance. Round 24 had registered its band conditional on a declared shape — four attributes, with a falsifier that would void the band outright if any of them departed. All four held, so the band was in force and the miss was scored honestly. The intake rule was not one of the four, and it had changed between the rounds the band was calibrated on and the round being tested — deliberately, on the previous round's own finding, with a measured effect of a factor of ten. A round that changes its detection instrument and then compares its rate to rounds measured with the old one is comparing two instruments. The falsifier could only range over the attributes somebody thought to list, and this is what that costs.

Then the band itself was measured, rather than judged. Across the round manifests, a band is written under eight distinct key spellings — and read by nothing: no hook, no checker, and no field of that kind exists in the series ledger at all. The eight spellings are themselves the evidence, because a field with no consumer has nothing holding its name still. A ruling on 2026-09-11 retired band registration on those grounds, together with a ratio nobody enjoyed publishing: over one recent round, the series had written 2.4× more prose about itself than product, and several of that round's headline findings were defects in machinery whose only customer was the machinery.

what was retired, and what explicitly was not

Retired: predicting a numeric range before a round and grading the round against that range. Kept: the admission rubric, the classification rules, grader independence, the version stamp on every row, and the rule that a comparison spanning two rubric versions has to say so at the point of comparison.

The stated reason is the sharpest sentence in the whole exercise: “those make an observation comparable and keep a party from grading itself. A predicted range does neither.” The measurement did not get weaker — the prediction wrapped around it did, and it had been carrying credit for work the rubric underneath was doing. Recording the instances is cheap and keeps findings from vanishing. Predicting a rate from them was the expensive half and the one that kept breaking.

The person who made that ruling then got the ratio wrong on the first pass, in the series' own registered failure mode. The window had no fixed endpoint, so it ran to the current tip and counted the very commits being written to record the ruling — the figure moved by one line between two readings in the same sitting, and the first pass said 2.5×. A counter whose window is opened by an external caller measures the caller. Both records now name the endpoint commits so the number is re-derivable. It is worth saying plainly that this happened on a figure about measurement discipline, in the decision that retired a measurement, made by the one participant who is not a session.

One series this page will not plot. Every round from 7 on enumerates its own coordinator errors at close, and the counts run 6 to 23. They are not plotted because successor rounds disagree with their predecessors about the totals — round 10 recounts round 9 as 19 errors where round 9's own row says 8, and round 12 revises itself from 14 to 23 after a closing session ran the checks that round had only read. No round has claimed its error rate improved, and none could: the counts are lower bounds that move, with no denominator anywhere in the series. What is measurable is the split — how many were caught by a party other than the one that made them: 6/13, 14/22, 7/23, 4/7, 9/11, 6/8, 7/12, 5/7, 5/6, 8/14 across rounds 10 to 20. It does not move in one direction, the worst round sits between two of the better ones, and the best is not the most recent. Round 18's pair is the weakest in that list and its own record says so: no error block was written at close, so the count was reconstructed afterward and disagrees with the round's sealed claim. Rounds 19 and 20 are the only two that are not lower bounds, because both had a closing session that audited the coordinator's self-report rather than totalling it.

Grading the grader

Twenty-four rounds counted defects without a written rule for what counted as one, who was allowed to decide, or what a number from one round was comparable to. Every figure in section 02 was produced under those conditions. The rubric that arrived at round 24 is the most transferable artifact the series has, and the first thing it did was move the headline number by a factor of ten without the work changing.

The admission rule changed the rate ten-fold, and the work did not change

Until round 24, an observation reached the tally if somebody filed it under the heading the tally expected. That is intake matching a label rather than a shape, and it is the same defect as everything in section 02, one level up: the count reads as a measurement of the round and is a measurement of what people remembered to label.

A factor of exactly ten, and it survives to four decimal places. Nothing about the work moved between those rounds; the admission rule did. The replacement is four binary items: a claim was made; something about it was wrong, or could not support what it was used for; it is locatable at a source; it is not already counted somewhere else. It is binary on purpose, because two graders rarely mean the same thing by a 3. It also carries a required disposition of insufficient evidence, so a grader forced to guess is not producing something indistinguishable from a judgment.

Two things have to be said beside that figure or it will be read as something it is not. First, the numerator counts every admitted near-miss regardless of which party produced it, including the coordinator's own, while the denominator contains no coordinator at all. So “per worker” is a detection-posture index, not a per-person error rate, and the rubric names it exactly that. Second, it did not revert: the following round came in between 8 and 9 on the same measure. What does not survive is any claim of stability. Three rounds, three rubric versions, and a single new admission item moved the figure by 0.4 — which is the versioning rule demonstrated against the number its own author was most pleased with, and that is the most useful place for it to land.

The most-quoted figure in the round was wrong by one, in one direction

Round 24 recorded that 18 of its 33 scored instances were the coordinator's own errors — the number that led the round's summary, fed the per-worker error rate, and went to the ledger. The coordinator classified all 33.

A separate closing session re-derived the attribution independently and found 19. The one it had missed was a guard the coordinator itself had written and broadcast to all three workers as a control; that entry's own text says, in as many words, that it is the coordinator's and not the worker's — and it appears in no enumeration of the coordinator's errors anywhere in the round. One omission, one direction, in the round's single most-quoted figure.

The fair reading is the one the rubric wrote down, and it is less satisfying than the story. That coordinator scored several of its own items that a strict reading would have routed out of the count altogether; every borderline call it made ran toward scoring itself. The defect was an omission under load. That is exactly what an independence rule is for, and exactly what diligence is not. The wrong number was not overwritten — it is still on the ledger row, still in the round's summary, still in what the tool prints — and the correction sits beside it, because editing it would tidy away the fact that it was ever wrong.

→The rule, and the one line that enforces itnarrated, then enforced

Any party records freely, including against itself, immediately. Self-reporting is the most productive habit in the series and nothing here slows it down. No party sets the score on an entry it owns — it records the entry with the classification left empty and a flag saying so, and a separate closing seat classifies. That seat does not classify its own entries either; those go to the one human in the loop, or forward to the next round. Where both parties own an entry, the human rules.

The mechanical form is a single comparison: the party that classified an entry must not be the party that owns it, on any entry that scored. The rubric says so in as many words — that is the one check that would have caught the round's headline — which is section 07's rule arriving early. Prefer the check that makes the class impossible over the correction of one instance of it.

06

Instructions that read fine and cannot be executed

Rounds 1 and 2 asked every worker to check in at fixed points. Across both rounds, the number of check-ins received was zero. Round 3 asked four workers for the same thing and all four complied, unprompted. Same coordinator, same model, same brief structure. The difference was one paragraph.

rounds 1–2 — 0 check-ins received

“Reply to the sender of this message for all checkpoints — do not ask for a session id.”

Why it cannot be run. The brief is delivered as the worker's opening prompt. There is no sender. The instruction names an affordance that does not exist in the situation it is describing, and the second clause forbids the one route that does work. It is not vague; it is precise about the wrong thing.

round 3 — 4 of 4 checked in

“To reach me, use the cross-session message tool. Find my session id by listing sessions — I am the one titled <coordinator>. Your brief arrived as your opening prompt, so there is no sender to reply to.”

Why it runs. It names the mechanism, gives a way to derive the address rather than assuming one, and pre-empts the wrong inference explicitly. Same request; now executable.

The fix turns on a small asymmetry that had to be discovered: a session cannot look up its own id, but it can be found by others under its title. So the address could never be supplied by the coordinator — it had to be made derivable by the worker. The general form: an instruction is real only if it names an observable trigger, a mechanism, and an address the reader can work out. Hand a human an impossible instruction and they ask a clarifying question. A worker session does something worse: it forms a reasonable belief that the channel doesn't exist, and proceeds without it.

The uncomfortable part. That paragraph was reviewed before it was sent, twice, and read as perfectly clear, because it is clear, to a reader. The defect was invisible from the writing side and only showed up as an absence, and absences are easy to miss. Same class as section 02: a brief that reads fine and does nothing is a plausible green. The standing assumption now is that an unexecuted instruction is under-specified rather than ignored.

Round 20 produced its two-instruction form, and it was created mid-round by the coordinator's own reordering. The briefs hard-decline force-push, unconditionally. Rebasing a branch that has already been pushed requires one. Under the original merge order the affected lease would never have needed to rebase, so the two instructions never met — then the coordinator changed the order for a good reason and told the lease to expect a rebase. Neither instruction is wrong. Their conjunction is unsatisfiable, and it did not exist until a reordering created it. The lease held its push and escalated rather than picking one of the two silently, which is the only reason this is an anecdote instead of an incident.

Writing the rule down is the weakest available intervention, and round 27 measured how weak

Everything above is about making an instruction executable. Round 27 asked the harder question — when an instruction is executable and its premise is stale, what actually catches it — and measured both candidate answers inside one round.

Round 27 — two ways to stop an instruction being acted on wronglyinstancescatches

The reason is structural rather than personal, and it is the argument for the whole receiving end of this pattern. A coordinator is the party most likely to be wrong about state, because it is furthest from the code and its instructions are stalest on arrival. A sender cannot fix staleness by trying harder. A receiver can detect it for the price of one command. Every premise caught that round was falsifiable in a single invocation — a revision count, one grep, one query against the tracker. Nothing that was caught required judgement, and nothing that required judgement got caught. A duty to “verify your instructions” that implies real work will be honoured on exactly the turns it matters least.

The eighth written rule is project memory, and the worker asked for it to be counted. A lease re-derived, mid-task, that a particular two-reference diff does not say which side moved. The persistent memory had carried that exact clause for two weeks: verbatim, specific to this project, with a first-person cost attached. “I nearly dropped my own commit on this.” It did not reach the party at the moment of need. They found it at close-out while deduplicating, after independently re-deriving the same lesson. The surface everyone assumes is exempt, our own prior finding, addressed to us, failed the same way the other seven did. It was added to the count at the worker's request, on the stated ground that it makes the ratio worse and the clause stronger.

A premise-check is pulled at the moment of use. A written rule — including one you wrote about yourself — is pushed in advance and has to survive until needed. Memory loses on exactly the axis a cheap check wins on. why the duty sits on the receiver and not on the sender

The second implementing clause is the one that ties this section back to section 01: the duty and the channel are one control. Twice that round a worker stopped and asked instead of acting, and both times that was possible only because it had an inbox and a coordinator that answered. The previous round's workers had neither — they were spawned as in-process subagents, where cross-session messaging is unavailable — so all three parties inherited a single session identity, a mid-round ruling could not be delivered to them, and the ledger could not tell them apart. A receiver expected to check a premise, with no way to report what it found, converts a caught error into an unlogged one. Spawning workers as separate sessions had always been justified as an observability requirement. It is also the precondition for the only control that worked.

Two disclosures the clause carries about itself, both of which make it weaker to quote and better to rely on. First: the coordinator that recommended the rule deliberately did not adopt it — a party writing a protocol clause about its own failure mode should not also be the party that enacts it. Second: measured again the following round, receiver checks came in at four of four, and two of the four were performed by the seat that reports the figure. A seat grading a control it exercised itself is the structure the independence rule in section 05 exists to prevent, and the record says so rather than leaving it to a reader. That record says three, not two. The list of four sits in the same object and names the party for each one; two of them are the reporting seat. An earlier draft of this page quoted the prose and did not read the list beside it, which is the defect this page is organised around, committed by this page, in the paragraph reporting the measurement of that defect. Writing a rule down does not make it bind — which the clause states about itself, on the ground that a clause about written rules failing cannot exempt itself from the finding.

the correction · and who made it

The diagnosis was also wrong, and a worker said so

The coordinator's first conclusion was that the reply path was structurally impossible — no sender, therefore no channel. A worker corrected it: “There was a channel. I didn't find it. Don't record ‘structurally impossible’ — that would fix the playbook in the wrong direction.” It had reached for the tool whose name made it the obvious first guess, been told no such recipient was reachable, and reasonably concluded no path existed. The real defect was narrower and more fixable than the coordinator's version of it, and the wrong diagnosis would have produced a workaround instead of a working address.

the coordinator wrote up its own merge error, blamed a command-line default, and proposed a fix. The lease disagreed with the diagnosis — “my DONE said ‘pushed, PR open, reported’ and also offered to fold more in. Those are contradictory. A terminal report containing an open offer is not a terminal report.” The coordinator had named the consequence; the lease named the mechanism. And the safeguard the coordinator proposed turned out to be the flag that exits zero having achieved nothing, so the lease's answer was not better than the coordinator's — it was the only one that existed.

The same lease also declined to guess. Having proven the safeguard did nothing, it refused to say why — flag not passed, or flag not honored — because it could not see the invocation and would not file a guess as a fact. That restraint is why the resulting issue is correct rather than merely plausible.

What catches these is a second reader whose purpose differs from the author's. Not a human, and not a gate. Human review does not scale and a gate cannot see intent. A second reader does both, and the only property that matters is that it is not the party that formed the belief.

Round 20 sharpened that into a rule the coordinator got wrong in its own favour. Its closing self-assessment read: “every time the hub checked a lease's claim by running something the lease had not run, it was productive; every time it passed a lease's reasoning along intact, it was the weak link. The value is in the different command, not in the second opinion.” The substance is right and the framing flatters the wrong seat — two of its five supporting examples are cases where the different command was run by a lease, on the coordinator. The corrected form is stronger and less flattering: the value is in the different command regardless of which seat runs it — and this round the coordinator was the subject of that command as often as its author. That is the argument for leases with standing to push back, rather than an argument about coordinator diligence.

Across every round, workers corrected the coordinator's premise more often than the reverse — the ordinary asymmetry between a lead and the person actually in the file, not a scoreboard — and the briefs came to say so out loud, granting explicit permission to reject the task's own stated reasoning. In round 3 four workers corrected the premise of their own assignment and two corrected the coordinator's. That is the pattern's error-correction path working, and it argues for writing the brief so it can be argued with.

07

Why it converges, and where it goes

A worker pointed at an area that has never been checked comes back with a pile of findings. The instinct is to read that as a pile of problems. It is usually one unlit area, and the pile is what a first light looks like.

the pattern

Burst, then silence

The first pass over an unmeasured surface returns a cluster of related findings. The second pass over the same surface returns very little. Nothing was fixed in between except the surface becoming observable.

the inference

Count areas, not items

A cluster of findings that share a root is one item of information, not N. Treating them as N inflates the apparent problem and produces N tracked tickets that all close for the same reason.

the consequence

This is why it terminates

If findings were independent, each round would uncover as many as the last and the backlog would grow forever. Because they cluster by unlit area, and areas are finite, successive rounds return less.

the caution

A quiet surface is ambiguous

Silence means the area is clean or that the thing looking at it is broken. That is section 02 again, one level up, so a quiet result is only trusted from a checker that has been shown to go red on a known-bad input.

→Prefer the enforcing check over fixing N instancesthe compounding rule

Given a burst of related findings there are two responses: fix each one, or build the check that makes the whole class impossible. The second is almost always right, because of what happens to each afterward. A tracked item accumulates forever — it sits in a backlog, gets re-read at every triage, gets re-prioritized, and costs attention every time someone scans the list, whether or not it is ever done. A check self-exits. Once it is green and wired to run automatically it stops needing to be thought about at all.

So the preferred output of a worker is not a list of corrections. It is one check, plus the corrections it forced, and a demonstration that the check goes red without them.

→Assert the state, don't pattern-match the intentthe design that came out of it

The best example came from the merge that closed nothing. The assignment specified a check that would scan pull-request text before merge and warn on the malformed shorthand. The worker refused the specified design and built the opposite: a check that runs after the merge and compares the items the text claimed to close against the items actually closed.

Its reasoning is the durable part — “a matcher guesses intent, an assertion reads real state, and only one of those has a false-positive class.” The evidence backed it: run against several hundred historical merges, the naive matcher produced 12 hits of which 3 were real, including a match that read a closure out of a heading which explicitly said the item stays open. The state assertion caught three distinct malformed shapes without being told any of them existed, because it never had to know what a closing phrase looks like.

The rule generalises: a warning that cries wolf gets muted within a week, and then the real one is invisible too. A noisy check is not a partial win over no check — past some false-positive rate it is worse than nothing, because it trains the reader to ignore the channel.

Two things that haven't been tried. This part is intent, not a description of anything that exists.

?A coordinator that runs its own next rounduntried

The loop hands the board to whoever starts the next cycle, and there is no particular reason that has to be a person. A coordinator could finish its round, evaluate its own worktree the way it evaluates a lease's, pull the next set of non-intersecting items off the board it just wrote, and go again. The obvious failure mode is the one this whole page is about: a cycle that runs clean and produces nothing, repeatedly, with no one reading the output. It would need the stopping rule before it needed the automation. Round 5's result bears directly on whether it is worth trying — if the absence of a context step at spawn survives a denser sample, the ceiling on a self-cycling coordinator is not context pressure, and the interesting constraint is somewhere else.

?Something above the coordinatorsuntried

Past some number of concurrent coordinators the merge problem comes back one level up — several finished worktrees, each internally consistent, that now have to land together in an order nobody has worked out. That is section 01 with bigger units, and it presumably wants the same answer: one writer, holding the ordering. Whether that tier is worth building depends entirely on whether the cost shape in section 03 holds at that scale, and there is no reason to assume it does. The reconciliation step is the expensive one, and a tier whose entire job is reconciliation is not obviously a bargain.
