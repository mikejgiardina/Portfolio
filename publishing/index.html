ENGINEERING CASE STUDY
IP DISCLOSURE CONTROL

Process design · defense in depth

Publishing out of a patent-pending codebase.

I write in public constantly — grant submissions, investor material, a portfolio, conference talks, an open clinical article library — and all of it is drafted inside private repositories that contain patentable mechanism. Every outward-facing file is a potential disclosure, and a federal filing is permanent and public the moment it lands. So publishing isn't a step at the end. It's a pipeline with seven stages, four audience tiers, and a written record of every place it has failed.

One registry feeds every stage. Three stages are automated; three are read — by an agent or by me. The automatable part of disclosure control is literal matching, and literal matching is the easy half. Paraphrase is the hard half, and no regex has ever caught it.

01

Why a checklist wasn't enough

The naive version of this is a pre-send checklist. I have one, and it's stage five — but on its own it fails for a specific structural reason.

asymmetry

The costs don't match

A late filing is recoverable. A disclosed mechanism in a filing that becomes public record is not. When one side of a decision is permanent and the other is an inconvenience, the process has to be biased, not balanced.

drafting reality

Public text is written in private repos

Outward artifacts are drafted next to the source they describe, because that's the only way the numbers in them stay true. The convenience that keeps claims accurate is the same one that puts mechanism a paragraph away from the public draft.

the actual failure mode

A quiet check reads as coverage

The write-time scanner reports nothing when a file is clean — and nothing when it never examined the file at all. Those two outcomes are indistinguishable from the author's chair, which is how a gap survives for months.

bias

I'm the worst reader of my own draft

I know what I meant, so I read past the sentence that gives the mechanism away. A hostile reader — someone whose only job is to find the disclosure — has to be a different reader than the author. That's a role, and roles can be assigned.

02

The pipeline

Seven stages, ordered by when they fire — from the moment a proprietary term is defined through to the record that goes to patent counsel. Each stage catches a class the stage before it structurally cannot.

01The term registrysingle source of truth

One versioned file holds every proprietary term, each paired with a replacement hint — not just “don't say this” but “say this instead.” Nothing downstream hardcodes a term; every later stage reads the registry at run time, so adding one term propagates to the scanner, the scrubber, and the reviewer at once.

The replacement hints carry a rule: a rewrite must preserve the claim, dropping only to the next-lowest useful specificity. Sanitizing a capability into vagueness is a different failure — it protects the IP by making the work sound like nothing.

02Write-time scanautomated · fires on every edit

A lifecycle hook fires after any write to a file under an outward-facing path and flags registry terms immediately, while the sentence is still on screen. It's the cheapest stage and it catches the largest volume — the flat, literal mistakes.

It is also the narrowest stage, in two ways: it only sees paths matching a set of globs, and it only fires on write and edit events. Both limits are documented at the top of the script, next to the incident that revealed them.

03The scrub loopon demand · rewrites

A packaged skill takes a target file and runs scan → propose rewrite → apply → re-scan, looping until the file comes back clean, capped at five passes before it hard-fails with a report naming the stubborn terms.

The re-scan is why it loops. A single-pass rewrite can introduce a second listed term while removing the first, and a capped loop that reports failure honestly beats an uncapped one that quietly declares success.

04Hostile-reader reviewspecialist agent · assumes nothing ran

A dedicated review agent reads the finished artifact end to end and returns a verdict. Its brief is explicit: assume nothing upstream ran. It exists because stage two is a path filter, and a path filter cannot protect a directory nobody told it about.

It hunts what a pattern can't express — mechanism described accurately enough to reimplement regardless of vocabulary, internal architecture nomenclature, scale figures that don't trace to a named source, overclaiming verbs, and credential drift. Three rules shape it: it reads the registry fresh every run rather than working from memory, it never edits the artifact (findings only, so a human applies every change to a public document), and it may not report clear on a file it did not read in full.

05The publish checklisthuman · pre-flight

A written pre-flight run top to bottom before anything leaves for a non-NDA audience. Universal checks first — scrubber clean, claims linter clean, a manual paraphrase eyeball with the registry in mind, every numeric claim re-derived from source rather than memory, no “shipped” or “production” language for things that aren't, patent scope not overstated into adjacent territory nobody filed on.

One item is a taste rule rather than a safety rule: no count-stuffing. A pile of impressive-sounding totals is impressive once and exhausting twice. Lead with what the system does, not what it contains.

06The publish gateautomated · fires on the push

The last automated thing that happens before anything leaves. It hangs off the push, not the file path: when the destination is one that publishes on receipt, every changed file in the outgoing commits is scanned against the registry — whatever directory it sits in.

This stage exists because stage two's scoping failed three times in two months. A push is the choke point — nothing reaches a public destination without one — so gating it takes path matching off the critical path entirely. It fails closed, but only for destinations that publish; everywhere else it exits without an opinion. A gate that blocks everything gets switched off within a week, and a gate that is switched off is worth less than no gate at all.

07The counsel queuerecord · same session

When engineering work touches the patent thesis, a review packet is filed in the same session the work lands — monotonically numbered, never renumbered, held in a directory excluded from version control. The bodies never enter a tracked repo; only an existence-and-status pointer does, so the queue is auditable without being disclosable.

The same-session rule was bought the expensive way. One early packet had to be reconstructed retroactively because the queue didn't exist when the work landed, and the recipe for a piece of engineering — the context, the path that produced it, the prior-art comparison — decays much faster than the code does. The marginal cost of filing now is small; the cost of waiting grows every week.

03

Weighted by destination

“Is this safe to publish?” has no answer without a destination. The same paragraph can be fine for a clinical audience and unrecoverable in a federal filing, so the review agent asks where an artifact is going — and, when it isn't told, states the tier it assumed.

DestinationAssumptionBar
Government / public-record filing The full text becomes public and permanent, and a competitor reads it. Strictest. No mechanism detail survives this bar — not paraphrased, not partial.
Investor No NDA unless one is signed and in hand. Mechanism out. Every number must survive diligence and trace to a named artifact.
Public web / portfolio / press Permanent and search-indexed. Benefit framing, not mechanism. this page
Conference / clinical Expert audience, sympathetic but sharp. Mechanism still out; every clinical claim needs a named source.

04

The output contract

The review stage returns a fixed shape. Verdict first, no preamble. Every finding quotes the offending text and names the replacement, because a category label without the sentence isn't actionable. And the last section is the one that keeps the whole pipeline honest.

VERDICT: BLOCK | REVISE | CLEAR
  one sentence — and if BLOCK, the single reason

BLOCKERS  — must fix before this leaves the repo
  file:line   category   the offending text, quoted
              └─ why it is a disclosure, and the replacement to use

REVISIONS  — should fix, not fatal
  file:line   category   quoted text
              └─ suggested rewrite

UNVERIFIED CLAIMS
  the claim  →  what it must trace to  →  traced? yes / no

COVERAGE
  files read · sections skipped and why · whether the automated
  scan would have caught each blocker on its own

Every review reports which findings the automated stage would have missed — so the pipeline measures its own front end continuously, from real artifacts rather than from a test fixture. A review that keeps reporting “the scanner would have caught this” means the human stages are wasting effort. A review reporting the opposite is telling me exactly where the next check belongs.

Two anti-softening rules ride alongside it: a blocker is never downgraded to a revision because a deadline is close (say it's a blocker, let the human override on the record), and a sampled read caps the verdict at revise — clear requires having read the whole thing.

05

Where it has failed

A disclosure-control write-up that only lists controls is marketing. These are the three failures on record and the gap still open — all four documented in the repo, at the top of the scripts they affect, next to the fix. Two of the three are the same failure.

failure · found july 2026

A plural directory name

The write-time scanner's path filter listed the singular form of a directory name. The live directory was the plural. Every file in it — including a federal grant packet, the single most disclosure-sensitive artifact class in the entire workspace — fell outside the filter entirely.

The scanner didn't fail. It ran, matched no path, and exited clean, every single time. From the author's chair that's identical to a passing scan. The packet was drafted with zero scan coverage while the tooling reported success.

Fixed by adding the pattern, but the real fix was the conclusion drawn from it: path-glob scoping is brittle by nature. The script now says so in a comment, and the reviewer agent — which reads finished artifacts regardless of where they live — was promoted from nice-to-have to the pre-publish gate of record. One layer's structural blind spot became another layer's job description.

failure · found july 2026 · third instance

The same miss, on this page

Two permanent, search-indexed case-study pages — including the one you are reading — were drafted in a directory the filter had never been told about. Same silent shape as the packet above: the scanner ran, matched no path, exited clean. It was caught only because the review stage was run by hand.

Three instances of one bug in two months, each “fixed” by adding another pattern, is no longer a bug. It's the design. Whether something will be published is not a property of its path — so a hand-maintained list of paths will keep missing new public surfaces as fast as they are created, and keep missing them silently, which is the part that matters.

That produced stage six. The automated check now hangs off the push rather than the path, which takes path matching off the critical path entirely. The filter stays as an early warning; it is no longer the thing standing between a draft and the public. Its remaining gaps became a latency problem — you find out later — instead of a silent-hole problem.

failure · found june 2026

Enforced on the map, absent on the machine

Before the failure above, the same scanner spent an unknown stretch as a complete no-op for a different reason: it read the edited file's path from environment variables the runtime no longer set, so the path came back empty and it bailed on the first line. Its warning also went to a stream the wiring discarded. Two independent bugs, stacked, both silent.

Meanwhile the process register listed the discipline as enforced. It was found by accident, while editing a neighbouring hook — not by any check.

This is what produced the standing rule now applied to every gate in the workspace: a check that exists is not a check that bites. Proving it goes red on a known-bad input is a separate, mandatory step from writing it. That rule, and the ledger tracking it, is its own write-up.

open gap · tracked, not fixed

The paraphrase hole

The registry catches a proprietary term written literally. It does not catch the same mechanism described in plain English by someone who understands it — and architecture described accurately enough to reimplement is a disclosure regardless of vocabulary.

So the discipline is enforced at the literal layer and narrated at the paraphrase layer. It sits on the conversion backlog with a named target: a fuzzy pattern family per protected term, failing on near-matches under outward-facing paths.

It is not fixed. It's ranked — the highest-leverage item still open — and covered in the interim by the two human-read stages.

What this is really a case study in

Not IP paranoia — layering controls against known blind spots, and knowing which blind spot each layer covers. Every stage here was added because the stage before it failed in a way I could name. The human stages exist because literal matching cannot catch paraphrase. The newest automated stage exists because the oldest one was scoped by file path, and three separate misses were what it took to accept that path is the wrong thing to key on.

The through-line is the same one that runs through the rest of this workspace: a check that fails quietly is worse than no check, because it reads as coverage you don't have. The answer isn't more scripts. It's pairing every automated gate with a reader whose job is to assume the gate didn't run — and writing down what it missed, every time, so the next check is chosen from evidence instead of instinct.
